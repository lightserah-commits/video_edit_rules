# 赤枠を決める係の仕事（AI動画編集 v002。1人で全部の束を決める。07 の read_frame）

あなたは YouTube 動画の編集の「赤枠を決める係」です。画面を映している間、話している中身が画面のどこかを赤い四角で囲みます（見る人が「どこの話か」を分かるようにする）。束（`batch_NN_in.json`）を順に全部読み、字幕ごとに `batch_NN_out.json` を書いてください。迷う所は枠なし（null）にして、reason に書いてください。**Addness には触らないでください。**

**使う量の決まり（大事）**：会話は20万トークン・やり取り40回まで。画像は1枚が重いので、**文字認識（束の中の行と位置）でまず決め、文字認識だけでは決められない字幕だけ画像を見る（全部で40枚まで）**。同じ画面が続く所は1枚見れば足りる。上限に近づいたら、そこまでの束を書いて終わる（残りの束は返す値の left に書く）。

2. ~/Desktop/video_edit_rules/07_画面共有とワイプ.yaml の read_frame・wipe・demo_label（枠が右上のワイプ・左上の札・字幕・強調の帯にかからないこと）
3. 束（10束）：**`~/Desktop/みかみ案件依頼書/AI動画編集/edit/analysis/赤枠_v002/batch_NN_lite.json` を読む**（`_in.json` は文字認識の全部の行が入っていて重すぎるので読まない）。lite の1字幕＝id・話者・字幕の文字・frames（png の名前・screen_frame・**match＝字幕の言葉と重なる画面の行（上位4つ）**・big＝大きい文字2つ・n_lines）。box は [x, y, w, h]（画像の左上が 0,0、0〜1）。画像は `~/Desktop/みかみ案件依頼書/AI動画編集/edit/analysis/screen_ocr_v002/frames/<png の名前>`（その時刻ちょうどの画面）。Read で見られる

- 字幕が「∅」の所（流している動画）は枠なし

## 決め方（README の要点）
- `rect`＝画像の 0〜1 の [x0, y0, x1, y1]。囲むのは話している要素（読み上げている文・図の箱・ボタン・行・数字）。行の一部だけを読む時はその部分に絞る。文字認識の x・y・w・h（0〜1）から位置を作る
- 枠なし（`rect: null`）：話している物が画面に映っていない・画面全体の話・切り替え中（読み込み・描いている途中）・ボタンの文字にたまたま当たっただけ・聞き手の相づち・雑談・AI に声で頼んでいる間（入力欄が空のまま）
- 同じ所の話が続く字幕は、**`group` と `rect` を全く同じ値**にする（1つの枠として出したままになる）。話が移ったら枠も移る
- 字幕の途中で画面が替わる（スクロール・ページ・メニュー）時は `splits`（替わる画面録画のコマ `at_screen_frame` から別の `rect`。`null` で枠なし）
- **Loom の顔の丸・左上の札（約 [0.0, 0.0, 0.3, 0.12]）・下の字幕（約 [0.0, 0.80, 1.0, 1.0]）にかかる枠は、かからない形に縮めるか枠なし**
- `reason` に、字幕のどの言葉が画面のどこを指すかを短く書く（確かめる AI が読む）
