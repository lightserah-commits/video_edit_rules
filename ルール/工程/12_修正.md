# 12. 修正（修正指示の受け方）

- ユーザーは動画を10分ほどずつ見て、音声入力で修正指示を出す。聞き取りの誤りがある（例「民調」＝明朝、「サードトラップ」など）
- **作業の前に、指示を言葉で整理して見せ、確認をもらってから直す**（全体に効くもの／時刻ごと、私の理解、分からない所の質問、この後の区間にも当てはめる提案）
- 時刻は、ユーザーが見ている版の時刻とは限らない（前の版の時刻のことがある）。字幕の中身で、どの字幕のことか確かめる
- 修正は版ごとにフォルダを分けて作り直す（判定の元のファイル＝`plan_vNNN.py`・`cut_vNNN.py` を直して、元から組み立て直す）。流れの実例：`tools/case_template/1027_v003/v003/_work/rebuild_all.sh`（cut → 赤枠 → Premiere で BGM・画像・赤枠を置く → 組み立て → Premiere でディゾルブ・保存）
- 作り直しは1本のスクリプト（例 `_work/rebuild_all.sh`）に全部の段（台本 → 字幕の位置 → カット → 図解・画像・赤枠の時刻 → 土台 → 組み立て → 検査）を入れて元から流す。組み立てた物だけを直す一回限りのスクリプトは作らない（作った時は rebuild に入れる。時刻は「目印の字幕＋ずれ」で持ち、カットが変わってもずれないようにする）
- Premiere の上で直接直して保存すると、作り直した時に消えるので、ユーザーが手で直した所は時刻を教えてもらうか、`tools/diff_user_edits.py` で AI の最後の組み立てと比べて読み取る（開いたままの直しは `--live` で読むだけ）。読み取った直しは表にして、意図を言葉にして OK をもらってから当てはめる
- 尺やカットが変わったら、後ろもすべて再検査する（`08` の cut.after_change）
- 直した中で他の区間や他の動画にも当てはまることは、案件のゴールの本文の「ルールに戻す候補」に積む（ルールに入れるのは定期の見直しの時）
- 根拠：2026-09-26 ユーザー指示

## C. 修正を頼む

音声入力でよい。版と時刻（前の版の時刻でもよい）と、どうしたいかを話す。AI は作業の前に指示を整理して見せる（工程12）。
Premiere で再生しながら話した画面収録（Loom など、声つき）で頼んでもよい。AI は声を時刻つきの文字にし、画面の再生位置のタイムコードを文字認識で読んで、どの所の指示かを合わせる（例 環境設定 v003：`tools/case_template/古い版/環境設定_v004/analysis_指示_v003/`。Loom の文字起こしがあればそれも貼ってもらう）。
Loom のリンクだけ渡された時（2026-10-17 セキュリティについて v003）：
- 言葉は Loom のプレーヤーの自動字幕から取る（アプリ内のブラウザで開き、video 要素の字幕トラックの区切りを時刻つきで読む。文字起こしの欄は登録しないと途中までしか出ない。登録はしない）。自動字幕は聞き違いが多い（「シュールテロップ」「和車テロップ」など）ので、画面と前後の言葉で読む
- 再生位置は、Loom の動画を**音を出さずに止めて**（muted・pause）指示ごとの画面を見て、映っている版の字幕・テロップで「どの版のどの時刻か」を合わせる（QuickTime などで流していてタイムコードが読めない時）。合わせた表は `edit/analysis/レビュー_vNNN_<日付>/loom_transcript.txt`
- 整理した一覧（全体に効くもの・時刻ごと・質問）は**チャットに全文を出す**。ファイルとボタンだけで OK をもらわない（2026-10-17、一覧を出さずに「OK」のボタンだけを出して、小川さん「修正点の一覧の確認は？」）

```
{版}の修正。{MM:SS} {今の状態} → {こうしたい}。{MM:SS} …
```

分からない項目は「おまかせ」でよい。AI が推測で決められない所だけ、最初に1回まとめて聞く。
